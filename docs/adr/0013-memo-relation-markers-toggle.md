# 随笔关系注释与待办/收藏强取消开关

## 状态

已采纳

## 背景

首页滑动「加入待办」每次都会 `createItem` 一条新任务，同一随笔可被反复加入，造成待办列表噪音。收藏侧仓库虽对锦囊 `NOTE_REF` 有一定幂等，但 UI 始终提示「已收藏」，且没有「再操作一次取消」的开关语义。

待办任务与随笔之间没有外键；收藏在锦囊侧有 `refLocalUuid`/`refId` 可反查。产品要求用随笔文末、界面日常不可见的 HTML 注释记录关联，并在再次操作时强取消。

## 决策

1. **待办转换**与**收藏切换**均为开关：再次操作 = **强取消**（删除对应实体 + 去掉关系注释）。已完成的待办任务取消时同样删除，不保留完成记录。
2. **关系注释**写在随笔 `content` 末尾，规范为：
   - `<!-- xinliu:YYYY-MM-DD:TODO id=<todoItemId> -->`
   - `<!-- xinliu:YYYY-MM-DD:FAV id=<collectionItemId> -->`
   日期为首次标记的本地日历日（仅审计）；权威字段是类型 + id。同一随笔最多一条 TODO、一条 FAV，可并存。
3. **判定双向探测**：先注释，再实体。收藏可按内置「收藏」文件夹下 NOTE_REF 反查；待办上线后靠注释内 id（历史重复任务不自动合并）。实体权威：注释失效则惰性清注释后按未转换处理；有实体无注释则补写注释、不新建。
4. **写序**：先实体后注释；写注释失败则补偿撤销刚建实体。写/剥注释**不**刷新用于时间线排序的更新时间，但仍标记需同步。
5. **可见性**：应用内读路径（纯文本预览、TalkBack、分享、待办标题派生、搜索）剥除关系注释；Markdown 富预览依赖 HTML 注释不渲染；编辑器仍展示原文。
6. **入口**：所有「从随笔生成待办」与「指向内置收藏文件夹」的入口（含滑动与加入锦囊对话框选中「收藏」）共用同一领域操作；其它锦囊文件夹仍为普通加引用。
7. **反馈**：轻量 Toast（已加入/已取消/已重新加入/已标记…）；列表轻量角标与开关同版交付。
8. **多端**：content 与实体各自同步、最后写入胜；冲突靠双向探测自愈，不做全库对账或冲突弹窗。升级后收藏角标优先实体反查，注释惰性补写。

## 后果

- 必须集中 `toggle` 领域操作与注释解析/剥离工具，避免 UI 各写一套。
- 需扩展仓库能力：按 id 删除待办、从收藏移除 NOTE_REF、静默更新 memo content（不碰排序时间）。
- 编辑器可见注释，高级用户手删注释后依赖双向探测与惰性自愈。
- 待办历史重复项无法可靠合并，只保证本功能上线后不再新增重复。
- 与 ADR 0011 兼容：收藏仍是锦囊内置文件夹，不引入真删除；本 ADR 只把「加入收藏」升级为可逆开关并增加随笔侧标记。

## 备选方案（未采纳）

- 仅 UI 防抖、不写注释：无法跨端/重启后判断，取消无依据。
- TodoItem 增加 `sourceMemoUuid` 字段：可查性更好，但要迁移与同步模型；首版用注释内嵌 id 更贴产品表述。
- 升级全量扫库补注释：易引发同步风暴；改为角标靠实体、注释惰性补写。
